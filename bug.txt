  Yes, it's a component-level bug, and it should be fixed in 4AF. The app-side iconForValue is a correct workaround, not the real fix.

  Here's the reasoning. iconFor is:

  icons.get(value) ?? (value == null ? undefined : iconForValue?.(value))

  That first term — the registry — can never be populated at the moment it matters. On first paint the popup hasn't mounted, so no SelectItem has registered anything. It only starts working after the user
  opens the panel once. So it's a fallback that is guaranteed absent exactly when the closed trigger first renders, and silently present afterward. That's the worst failure shape: it looks fine the moment
  you click to test it, and it's broken on every cold load.

  The decisive evidence that this is an oversight rather than an intended contract is 20 lines up — labelFromItems, whose doc comment describes this exact bug for the label path:

  ▎ …shows the raw value ("updated") until the panel is opened once and the items register their labels.

  Somebody already hit this, understood it, and fixed it — for labels only. The icon path never got the symmetric treatment.

  The fix I'd make

  Mirror labelFromItems. Purely additive — nothing that works today changes:

  function iconFromItems(items: unknown, value: unknown): ReactNode | undefined {
    if (!Array.isArray(items)) return undefined;   // the record form is {value: label}, no icon slot
    return (items as { value: unknown; icon?: ReactNode }[])
      .find((item) => Object.is(item.value, value))?.icon;
  }

  const iconFor = useCallback(
    (value: unknown) =>
      icons.get(value)
      ?? (value == null ? undefined : iconForValue?.(value as Value) ?? iconFromItems(props.items, value)),
    [iconForValue, icons, props.items],
  );

  The one real cost: items is Base UI's prop, typed ReadonlyArray<{label, value}>, so SelectProps has to Omit<..., "items"> and re-declare it with an optional icon. Additive and backward compatible, but it
  is a public API change to your library.

  The payoff is that a Select declares each option once and both its label and its icon resolve before mount:

  items={options.map((o) => ({ value: o.value, label: o.label, icon: <Icon /> }))}

  iconForValue stays for computed icons and for Selects that don't pass items.
