## API

**Main exports:** `SearchSelect`, `SearchSelectInput`, `SearchSelectContent`, and item parts

An editable Combobox-style trigger with live filtering, single or checkbox-based multi-selection,
icons, and full keyboard and ARIA behaviour.

## Searching and cancelling

In single-select mode, the committed selection appears as dimmed placeholder text, including
while focused. Typing starts a fresh query over it. Clicking outside or pressing Escape
discards the query and restores the same dimmed selection; deleting the query also preserves
the choice. Choosing a row commits a new selection. Opening highlights the current selection,
while typing highlights the top match. When the selection has an icon, focusing replaces it
with a dimmed search icon; leaving the field restores the selected option’s icon.

`inputValue` / `defaultInputValue` and `onInputValueChange` represent the search query,
separately from `value` / `defaultValue` and `onValueChange`. `itemToStringLabel` also supplies
the selected placeholder for custom item shapes. Multi-selection retains its existing count
summary and checkbox behavior.

## Sizing

`size="sm"` is the 30px compact control and `size="md"` is the 34px form-row control.
The input trigger and its option rows share the selected size, and the input uses the matching
button radius: 6px for `sm` and 8px for `md`.

## Item data

The Combobox value may carry its own icon. An item is its value—`<SearchSelectItem value={item}>`—
so there is no key to look up in a separate mapping. Put the icon on each item object when a
preselected value must resolve before the popup has mounted:

```tsx
const fruits = [{ value: "apple", label: "Apple", icon: <Apple /> }];

<SearchSelect items={fruits} defaultValue={fruits[0]}>
```

No type change is needed: Base UI types Combobox `items` as `readonly any[]`, and this convention
extends the `{ value, label }` shape it already treats specially. An icon passed only to
`SearchSelectItem` still cannot resolve before mount because nothing outside the popup has seen
it. Resolution order is the mounted item, then `iconForValue`, then the value's own `icon`.
