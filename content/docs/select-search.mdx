## API

**Main exports:** `SearchSelect`, `SearchSelectInput`, `SearchSelectContent`, `SearchSelectItem`,
`SearchMultiSelectItem`, `SearchSelectGroup`, `SearchSelectGroupLabel`, `SearchSelectCollection`

An editable Combobox-style trigger with live filtering, single or multi-selection,
icons, and full keyboard and ARIA behaviour.

## Sections

For grouped data, pass `items` as an array of `{ label, items }` groups. The content's render
function receives each filtered group. Render a `SearchSelectGroup` with that group's `items`,
a `SearchSelectGroupLabel` for its heading, and a `SearchSelectCollection` inside it to render
the filtered options with `SearchSelectItem` or `SearchMultiSelectItem`. Base UI owns filtering,
keyboard navigation, and the accessible connection between headings and options. Empty
sections hide their headings. Selected values remain individual items, not group objects.

## State-based classes and validation

The input, content, both item types, groups, and group labels accept a `className` string or
`(state) => string | undefined`, merged with their defaults. State comes from each Base UI
Combobox primitive: inputs include open and Field state, items include selected/highlighted
state, and popups include open/side/alignment state. The placeholder sizer uses the input's
resolved classes too, so state-based font and padding changes preserve its minimum width.

The input styles both `aria-invalid="true"` and Field's `data-invalid`, including while focused
or hovered. The error border and ring take precedence over either focus tone.

`SearchSelectInput` takes the same four looks as Select's trigger, set with `variant`; the input
carries `data-variant`.

| `variant` | Look |
| --- | --- |
| `default` | The boxed field. |
| `outline-ghost` | Button's `outline-ghost`: the `shadow-border` edge with no fill, so the background shows through, and a translucent wash on hover. |
| `ghost` | Button's muted ghost colours, filled `muted` on hover and while focused. |
| `plain` | No surface, edge, focus ring, or horizontal padding; the caret marks focus, and the leading icon and chevron sit at the text's edges. |

`tone` and the error border apply to `default` and `outline-ghost`; `ghost` and `plain` show the
error ring. Existing Field
labels, descriptions, and validation behavior remain connected.

## Popup placement

`SearchSelectContent` accepts `side` (default `"bottom"`), `align` (default `"start"`),
`sideOffset` (default `6`), and `alignOffset` (default `0`). Base UI still handles collision
avoidance. `portalProps` forwards Portal options such as `container` (an element or ref)
and `keepMounted`; Search Select keeps the portal mounted by default.

## Searching and cancelling

In single-select mode:

- The selected value shows in normal text, and dims while the field is focused. Typing starts a
  new query over it.
- Opening highlights the current selection; typing highlights the top match.
- Choosing a row commits it. Clicking a row also unfocuses the field; selecting with the keyboard
  keeps focus.
- Escape discards the query and keeps focus. Clicking outside, or deleting the query, keeps the
  current selection.
- When the selection has an icon, focusing the field swaps it for a dimmed search icon until the
  field loses focus.

In multi-select mode the panel stays open for more choices. Use `SearchMultiSelectItem` for
its rows: a trailing check that draws in as a row is selected and fades out as it is cleared.
`SearchSelectItem` shows the same
check in either mode.

`inputValue` / `defaultInputValue` and `onInputValueChange` hold the search query, separately
from `value` / `defaultValue` and `onValueChange`. `itemToStringLabel` also supplies the selected
label for custom item shapes. Multi-select shows a count summary while the input is unfocused.

## Sizing

`size="sm"` (default) is the 30px compact control and `size="md"` is the 34px form-row control.
The input trigger and its option rows share the selected size, and the input uses the matching
button radius: 6px for `sm` and 8px for `md`.
Single-select input text and icons align with their option-row counterparts at both sizes.
The trailing chevron shares Select and Select Aligned's inset, including in vertical button groups.

The input is at least as wide as its placeholder, including icon space, padding, and the
dropdown button. It also reserves room for the displayed selection or multi-select summary.
This minimum applies in button groups too; the field still expands to fill available space.
The panel is at least as wide as the input and grows to fit its longest visible row, up to
the available viewport width. Rows truncate only when that space runs out.

## Item data

An item is its own value (`<SearchSelectItem value={item}>`), so the icon goes on the item
object. Do this when a preselected value must show its icon before the panel has opened:

```tsx
const fruits = [{ value: "apple", label: "Apple", icon: <Apple /> }];

<SearchSelect items={fruits} defaultValue={fruits[0]}>
```

An icon passed only to `SearchSelectItem` is available after the panel mounts. Resolution order
is the mounted item, then `iconForValue`, then the value's own `icon`.

## Highlight implementation

Opening activates the current selection, or the most recently selected value in multi-select;
without a selection it activates the first enabled row. A query activates the top match, and
leaving the panel keeps the active row.

The Base UI integration uses `autoHighlight="always"` only when nothing is selected: that mode
pins the first row over an existing selection. With a selection, plain `autoHighlight` restores
it. Keep `keepHighlight` enabled so pointer exit does not clear the mark and reset Enter's target.
