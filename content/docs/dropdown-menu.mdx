## API

**Main exports:** root, trigger, content, item, checkbox, radio, submenu, shortcut, and
nested-select parts, plus `createDropdownMenuHandle`, `DropdownMenuPortal`,
`DropdownMenuPositioner`, and `DropdownMenuPopup`.

A Base UI menu with keyboard navigation, safe submenu pointer travel, and these row types:

| Row | Parts | For |
| --- | --- | --- |
| Item | `DropdownMenuItem` | A command or link, optionally destructive or with a shortcut |
| Checkbox | `DropdownMenuCheckboxItem` | An on/off setting, shown with a tick |
| Toggle | `DropdownMenuCheckboxItem indicator={false}` | An on/off setting carried by its icon and label |
| Radio | `DropdownMenuRadioGroup`, `DropdownMenuRadioItem` | One choice from a short set |
| Action | `DropdownMenuActionItem` | Work that runs, confirms, and reverts |
| Submenu | `DropdownMenuSub`, `DropdownMenuSubTrigger`, `DropdownMenuSubContent` | Navigation into more rows |
| Select panel | `DropdownMenuSelect`, `DropdownMenuSelectTrigger`, `DropdownMenuSelectContent`, `DropdownMenuSelectItem` | Single or multi-select in a nested panel |

`DropdownMenuLabel`, `DropdownMenuGroup`, and `DropdownMenuSeparator` structure the list.

Menus grow from a 200px minimum up to 20rem, while staying within the available width.
Long labels and unbroken URLs wrap in ordinary, checkbox, radio, action, submenu, and
nested-select rows. Shortcuts remain on the first line. Override the panel limits with
`min-w-*` and `max-w-*` classes when needed.

Rows left-align every Morph inside them and mute a morphing leading icon to match a plain one.
Don't pass `place-items-start` or a text colour at the call site.

## Shared menus

A stable `createDropdownMenuHandle<Payload>()` connects detached triggers to one
`DropdownMenu`. Each trigger supplies a typed `payload`, and the root's function child
receives the opening trigger's payload. This lets several row-action buttons share a menu
while acting on the correct row. Closing returns focus to the trigger that opened it.
`DropdownMenuHandle`, `DropdownMenuProps`, and `DropdownMenuTriggerProps` preserve the payload type.

## Portals and positioning

`DropdownMenuContent`, `DropdownMenuSubContent`, and `DropdownMenuSelectContent` accept:

- `portalProps`: `container`, `keepMounted`, portal refs, and other portal props.
  The existing top-level `keepMounted` shorthand takes precedence when supplied.
- `positionerProps`: a custom `anchor`, `collisionBoundary`, `collisionPadding`
  (8px by default), `collisionAvoidance`, `sticky`, `positionMethod`,
  `disableAnchorTracking`, positioner refs, and state-based classes.
- `side`, `align`, `sideOffset`, and `alignOffset` remain direct props.
  Offsets accept numbers or Base UI offset functions.

Refs, DOM events, `render`, and `className` on the content belong to the popup.
For a custom composition, use `DropdownMenuPortal`, `DropdownMenuPositioner`, and
`DropdownMenuPopup`; the popup retains Scroll Area and the menu's appearance.
`DropdownMenuContent` already includes those parts.

## State-based styling

Popup and positioner `className` props accept strings or callbacks receiving their Base UI
state, including whether the menu is open and its resolved placement. Item, checkbox, radio,
action, submenu-trigger, and nested-select row classes also accept callbacks. Row state includes
`highlighted` and `disabled`; checkable rows also expose `checked`.

The default styling is preserved and merged with the callback's result. Group, radio-group,
trigger, and separator parts retain their respective primitive class callbacks. Plain labels
and shortcuts take ordinary string classes.

## Item rows

`DropdownMenuItem` takes a leading icon, a label, and an optional `DropdownMenuShortcut`.
`variant="destructive"` colours the label and icon; `inset` indents a row without an icon to
line up with rows that have one.

A disabled row can take a `disabledReason`. Hovering the row then opens a tooltip on its right
explaining why, without the usual tooltip delay:

```tsx
<DropdownMenuItem disabled disabledReason="Billing is available on the Pro plan.">
  Billing
</DropdownMenuItem>
```

Checkbox and radio rows accept `disabledReason` too.

`DropdownMenuShortcut` uses [Kbd](/docs/kbd), installed automatically with the menu.
It accepts the same sizing, native props, refs, and `asChild` composition, with the shortcut
aligned to the row’s trailing edge and first line.

## Checkbox and toggle rows

`DropdownMenuCheckboxItem` is a `menuitemcheckbox`, controlled with `checked` and
`onCheckedChange` or uncontrolled with `defaultChecked`. By default it shows Checkbox's box and
its self-drawing tick in the leading slot.

`indicator={false}` drops the checkbox and its indent, so the row reads as a toggle and its icon
and label carry the state. `icon` and `children` may each be a function of checked state; the
row morphs between the glyphs:

```tsx
<DropdownMenuCheckboxItem
  indicator={false}
  icon={(checked) => (checked ? <BellOff /> : <Bell />)}
>
  {(checked) => (
    <Morph activeKey={checked ? "on" : "off"} items={{ on: "Unmute", off: "Mute" }} />
  )}
</DropdownMenuCheckboxItem>
```

Use `fillIcon` instead when the glyph keeps its shape, such as a bookmark, star, or heart that
only fills in.

### Deferred changes

An `action` makes the change wait on work, like Action Toggle. The row keeps its current state
while pending and calls `onCheckedChange` only after success; on failure the state is unchanged.
The loader takes the checkbox's slot, or the icon's slot on a toggle:

```tsx
<DropdownMenuCheckboxItem
  indicator={false}
  icon={(muted) => (muted ? <BellOff /> : <Bell />)}
  action={(muted) => setMuted(id, muted)}
>
  {(muted) => (muted ? "Unmute thread" : "Mute thread")}
</DropdownMenuCheckboxItem>
```

The children function also receives the action status as a second argument, for a row that
draws its own wait.

| Prop | Default | |
| --- | --- | --- |
| `action` | — | `(checked) => void \| Promise`; handed the state being moved to |
| `revertAfter` | `2000` | How long a failure shows, in ms |
| `pendingDelay` | `0` | Holds back the loader, in ms |
| `announce` | — | `{ pending, error }` screen reader messages |
| `onError` | — | Called with the failure |

## Radio rows

`DropdownMenuRadioGroup` holds one value across its `DropdownMenuRadioItem` rows, controlled
with `value` and `onValueChange` or uncontrolled with `defaultValue`. Each row shares Radio's white selection ring with an open center
in the leading slot. Head the group with a `DropdownMenuLabel`.

## Action rows

`DropdownMenuActionItem` runs an action, confirms the result, and reverts, like Action Button.
"Copy link" becoming "Copied" with a check is the typical case:

```tsx
<DropdownMenuActionItem
  icon={<Link2 />}
  action={() => navigator.clipboard.writeText(url)}
  labels={{ success: "Copied" }}
  announce={{ success: "Link copied" }}
>
  Copy link
</DropdownMenuActionItem>
```

The icon and label morph through pending, success, and error without resizing the row. The row
defaults to `closeOnClick={false}` so the result stays visible; set `closeOnClick` when the
result shows on the page behind the menu instead.

| Prop | Default | |
| --- | --- | --- |
| `action` | — | `() => void \| Promise` |
| `icon` | — | Resting glyph |
| `labels` | — | `{ pending, success, error }`; each falls back to the resting label |
| `icons` | Loader, check, triangle | `{ pending, success, error }` |
| `revertAfter` | `2000` | How long the outcome shows, in ms |
| `pendingDelay` | `0` | Holds back the loader, in ms |
| `announce` | — | `{ pending, success, error }` screen reader messages |
| `closeOnClick` | `false` | Whether a click closes the menu |
| `onSuccess`, `onError` | — | Called with the outcome |

## Submenus and select panels

Dropdown Menu includes three nested-panel forms:

- a navigation submenu (`DropdownMenuSub`);
- a single-select panel with the chosen value shown in the parent row and a checkmark in the
  panel (`DropdownMenuSelect`);
- a multi-select panel (`DropdownMenuSelect multiple`) using small Checkbox components and an
  `N selected` parent label.

Nested panels open immediately when their parent row is hovered by default; set the trigger's
`delay` to change that. The safe pointer corridor keeps them open while the pointer moves into
the panel, and the parent highlight stays active meanwhile. Hover-opening a navigation submenu
does not activate its first child; keyboard navigation moves the active highlight.

Select-style triggers keep their label or placeholder on the left and show the selected value or
selection count, dimmed, immediately before the chevron. `searchable` adds a plain search field
without a leading icon; the no-results state is the same height as one option row.

Select panels open with the selected row active, the most recent enabled selection for
multi-select, or the first enabled row in document order. They mark it with `data-panel-active`
and retain it when the pointer leaves a row. A query activates the first enabled match.
Searchable panels keep focus in the search field; Enter selects the active row, and Arrow Down
or Arrow Up moves focus to that row for Base UI keyboard navigation. With no active row, the
arrows start at the first or last enabled match. `autoFocusFirstItem={false}` opts out of
automatic activation and search-field focus.

## Loaders and pending work

`DropdownMenu loader={<MySpinner />}` supplies the menu's loading indicator, including portalled
rows. Omit it to inherit [LoaderProvider](/docs/reference/engineering#shared-loading-indicators),
with `ClassicLoader` as the fallback. Action and checkbox rows accept `loader` for one row; on an
action row, a custom `icons.pending` takes precedence.

Action and deferred checkbox rows announce their status from outside the row element, so the
status text never becomes part of the row's accessible name.

Closing the menu does not cancel an in-flight action. `onSuccess` / `onError` on an action
row, and `onCheckedChange` / `onError` on a deferred checkbox row, still report the outcome
after the row unmounts. Keep controlled checked state in the parent when it must survive
closing and reopening the menu.
