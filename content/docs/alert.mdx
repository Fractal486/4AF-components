## API

**Main export:** `Alert`

An inline status line—a glyph plus a sentence with no surface—in five variants: destructive
`error` with `role="alert"`, amber `warning`, green `success`, neutral `info`, and muted
`loading` with the ASCII spinner. The last four use `role="status"`. It renders nothing for an
empty message and carries no field context of its own.

## General inline status

Alert carries no surface of its own—no panel, no border, no padding beyond the space above it—and
has no field context. That lets the same line report a failed save, a passing check, or work in
progress anywhere a short status belongs.

```tsx
import { Alert } from "@/components/ui/alert";

<Alert>Could not save your changes.</Alert>
<Alert variant="warning">Sending will notify all 240 members.</Alert>
<Alert variant="success">Changes saved.</Alert>
<Alert variant="info">We'll only use this to send receipts.</Alert>
<Alert variant="loading">Checking availability…</Alert>
```

| Variant | Ink | Glyph | Announced as |
| --- | --- | --- | --- |
| `error` (default) | Destructive red | Hexagon alert | `role="alert"` |
| `warning` | Amber accent | Lucide triangle | `role="status"` |
| `success` | Success green | Lucide check | `role="status"` |
| `info` | Foreground ink | Lucide info | `role="status"` |
| `loading` | Muted grey | ASCII spinner | `role="status"` |

The inks match Badge's status colours value for value, so a line under a field and a badge beside
it read as one severity. The two neutrals differ by weight, not hue: `info` is full-strength ink
because it is a note meant to be read; `loading` is muted because work in progress is not yet an
outcome.

Only the error interrupts. `role="alert"` is right for something that has just stopped the user;
a caution, confirmation, note, or progress line uses `role="status"` and waits for a pause. The
loading spinner stays out of the accessibility tree—the line beside it is the announcement, so a
live region of its own would say “Loading” over the sentence explaining what is loading.

The glyph always occupies the same 14px slot, so a line moving from checking to saved or failed
swaps its glyph without shifting the text sideways. Installing `alert` brings `ascii-loader` with
it.

Reach for [Badge](/docs/badge) when status is a label on a row and [Toast](/docs/toast) when it
should arrive over the page rather than live in it. When an alert describes a specific field,
connect it to that field for assistive technology:

```tsx
<Input
  aria-invalid={Boolean(error)}
  aria-describedby={error ? "email-error" : undefined}
/>
<Alert id="email-error">{error}</Alert>
```

This component was called `FieldError` and installed as `field-error`. `Alert` is exported
alongside a deprecated `FieldError` alias, so existing call sites keep working; the install name
has changed outright.
