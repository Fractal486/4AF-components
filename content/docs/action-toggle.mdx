## API

**Main export:** `ActionToggle`

A toggle that runs an `action` with the next pressed state and commits it after the action
succeeds. The action may return a promise. Use `defaultPressed` (default `false`) for
uncontrolled state, or `pressed` / `onPressedChange` for controlled state; a controlled caller
must update `pressed` from `onPressedChange`. Use it for states such as Follow/Following
or Subscribe/Subscribed. Its appearance defaults to `variant="outline"` and `size="md"`.

While pending, the toggle keeps keyboard focus with `aria-disabled="true"` and
`aria-busy="true"`, and blocks repeat activation. An explicit `disabled` prop still disables
the native button.

By default the control keeps the width of its widest state. `sizing="current"` fits it to the
showing state and animates the width as it changes. The control carries `data-sizing`.

`loader={<MySpinner />}` supplies the pending indicator. Otherwise it inherits
[LoaderProvider](/docs/reference/engineering#shared-loading-indicators), defaulting to `ClassicLoader`.
A supplied `icons.pending` takes precedence.

Hidden sizing copies reserve the loader's space without mounting it. An idle toggle does not
run the supplied loader's timers or animations.

## Persistent state

[Action Button](/docs/action-button) shows a temporary outcome, then returns to idle.
Use Action Toggle when the new state should persist:

```tsx
<ActionToggle
  action={(following) => (following ? follow(id) : unfollow(id))}
  icon={<Plus />}
  icons={{ pressed: <Check /> }}
  labels={{ pressed: "Following" }}
>
  Follow
</ActionToggle>
```

It sets `aria-pressed`, which is why it is a separate component, as Toggle is from Button.

It is not optimistic. By default the label stays while the loader runs; `labels.pending` replaces
the pending label, and `pendingDelay` can defer the indicator (default 0ms). On failure it
shows the error for `revertAfter` milliseconds (default 2000) and keeps its previous state.
`onPressedChange` fires only on success, even if the toggle has unmounted while waiting.
`onError` also reports failures after unmount; unmounting does not cancel the action.

With `fillIcon` and no `icons.pressed`, the same glyph fills when pressed instead of being
replaced.
