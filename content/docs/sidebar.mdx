Shortcut hints use the shared [Kbd](/docs/kbd) component, installed automatically with Sidebar.

## API

**Main exports:** `SidebarProvider`, `Sidebar`, `SidebarPanel`, `SidebarHeaderButton`,
`SidebarTabs`, and the menu, group, submenu, action, badge, and skeleton parts

A responsive application sidebar.

### SidebarProvider

| Prop | Default | Description |
| --- | --- | --- |
| `open` / `defaultOpen` / `onOpenChange` | — / `true` / — | Controlled or uncontrolled desktop open state; the callback requests a new boolean state. |
| `persist` | `true` | Writes the accepted desktop open state to the `sidebar_state` cookie when it changes. Set `false` to disable writes. |
| `keyboardShortcut` | `"mod+b"` | Global toggle shortcut; `null` disables it. |
| `mobile` | — | Overrides the viewport breakpoint: `true` forces the drawer, `false` the desktop sidebar. |

The cookie stores `true` or `false`, uses `path=/`, and expires after seven days
(`max-age=604800`). There is no write on initial mount or when a controlled parent rejects
a toggle. The provider does not read the cookie automatically; an app that restores it must
read it and pass the result as `defaultOpen` or `open`. Mobile drawer state is separate.

### Sidebar layouts

- `variant`: `sidebar`, `floating`, `inset`, `split`, `split-floating`, or `split-inset`.
- Controlled or uncontrolled collapse, menu sections, nested rows, collapsible menu rows, badges,
  and loading skeletons.
- A full-width primary action in the header (`SidebarHeaderButton`).
- Split layouts pair `SidebarRailButton` controls, each with a `value`, with `SidebarPanel`
  sections. `activePanel`, `defaultActivePanel`, and `onActivePanelChange` select the wide panel.

`SidebarRailButton tooltip="Projects"` labels a rail icon. Moving between rail icons opens their
tooltips immediately, and the entrance transition still plays.

In a non-split desktop sidebar with `collapsible="offcanvas"`, collapsed navigation leaves the
tab order and accessibility tree once its exit finishes. If collapse happens while focus is inside, focus returns to the
external `SidebarTrigger` in the same provider, or the edge `SidebarRail` when present. Keep a
trigger outside the panel so keyboard users can reopen it. Icon and noncollapsing sidebars keep
their navigation available. `SidebarTrigger` sets `aria-expanded` to whether the panel it
toggles is open: the drawer on mobile, the sidebar on desktop.

Below 768px, collapsible sidebars and split layouts render as a drawer. A non-split sidebar with
`collapsible="none"` stays inline at every viewport size, with the same edge rule against the
content as the collapsible sidebars. For drawer layouts, `className` styles
the desktop sidebar; style the drawer with `mobileClassName`. The drawer slides in from the sidebar's `side` over a dim backdrop and slides back out (Base UI Dialog with CSS transitions).

## Keyboard shortcut

`SidebarProvider` accepts `keyboardShortcut`, defaulting to `"mod+b"`. Use `null` to
turn it off, or another combination such as `"mod+shift+s"`. Supported modifiers are
`mod`, `ctrl`, `meta`, `alt`, and `shift`; `mod` means Command on Apple devices and Ctrl
elsewhere. Modifiers must match exactly. The trigger's hint follows this setting.

When several sidebars share a shortcut, the one containing focus responds, including its
mobile drawer. Outside all of them, the first matching sidebar in page order responds.
Repeated, already-handled, and composing key events are ignored, as are shortcuts typed in
inputs, textareas, selects, or rich text editors.

## Mobile navigation

Following an ordinary link inside the mobile drawer closes it, including links handled by
client-side routers. New-tab links, downloads, modified clicks, and `aria-disabled` links
keep it open. Buttons and desktop navigation do not close the sidebar.

| Prop | Part | Notes |
| --- | --- | --- |
| `mobile` | `SidebarProvider` | `true` forces the mobile drawer and `false` the desktop sidebar at any width. Omitted, the 768px breakpoint decides. `SidebarLayout` passes it through. |
| `mobileContainer` | `Sidebar` | An element to open the drawer inside instead of `document.body`. The drawer and backdrop are positioned absolutely against it, so it needs `position: relative`; the drawer takes its height and at most 85% of its width. |

## Menu badges and actions

`SidebarMenuBadge` keeps accepting custom children. Its count and dot props add notification
indicators that remain visible as a small dot when the sidebar collapses to icons. Collapsing
into the icon rail, the count fades out over the first half (held by `data-hold`), becomes the
dot at the midpoint, and the dot fades in over the second half. Expanding, the count returns
with the row's `SidebarMenuAction`, fading in from the first frame.

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `count` | `number` | | Integer count. Zero, negative, and non-finite values hide the badge. |
| `max` | `number` | `99` | Larger counts show the cap followed by `+`. The full count stays accessible. |
| `animated` | `boolean` | `false` | Opts into the shared Number Animation through BadgeCount. |
| `locales` | `Intl.LocalesArgument` | `"en-US"` | Number formatting locale. |
| `dot` | `boolean` | `false` | Show a status dot in expanded mode too. |
| `tone` | `"default" \| "success" \| "warning" \| "destructive"` | `"default"` | Count or dot color. Custom classes can override it. |
| `label` | `string` | | Accessible description, such as “unread messages”; names a standalone dot. |

`SidebarMenuAction replacesBadge` shares a sibling badge's position on devices with a fine
pointer. The badge gives way to the action on hover, keyboard focus, or while its menu is open.
Touch devices keep both visible in separate slots. In icon mode the action hides and the
notification dot remains. `showOnHover` is implicit when `replacesBadge` is enabled.

Sidebar reuses `BadgeCount` for formatting and optional number animation; it installs Badge
and its Number Animation dependency. Existing text badges and actions keep their behavior.

## Menu control geometry

`SidebarMenuButton` supports `size="sm"`, `size="default"`, and `size="lg"`. The compact
`sm` row uses a 6px radius; `default` and `lg` use an 8px radius. In the icon rail, rows are
32px wide; `default` and `lg` rows are 32px tall, and `sm` rows keep their 28px height. Nested
`SidebarMenuSubButton` rows use a 6px radius, and fixed split-rail buttons are 32px squares
with an 8px radius.

## Collapsible menu sections

`SidebarGroup` provides visual grouping but does not own open state. For an expandable menu
row, use `SidebarMenuCollapsible` with `SidebarMenuCollapsibleTrigger` and
`SidebarMenuCollapsibleContent`:

```tsx
<SidebarMenu>
  <SidebarMenuCollapsible defaultOpen>
    <SidebarMenuCollapsibleTrigger>
      <Folder />
      <span>Projects</span>
    </SidebarMenuCollapsibleTrigger>
    <SidebarMenuCollapsibleContent>
      <SidebarMenuSub>
        <SidebarMenuSubItem>
          <SidebarMenuSubButton href="/projects/acme">Acme</SidebarMenuSubButton>
        </SidebarMenuSubItem>
      </SidebarMenuSub>
    </SidebarMenuCollapsibleContent>
  </SidebarMenuCollapsible>
</SidebarMenu>
```

The trigger includes a trailing `ChevronDown` that points right while closed and down while
open. Pass `chevron={false}` when the trigger supplies its own indicator. A sibling
`SidebarMenuAction` sits just before the chevron, and a sibling `SidebarMenuBadge` takes its own
slot before both, so they never overlap. Hovering a nested row highlights only that row. The
collapsible root accepts Base UI's `defaultOpen`, `open`, `onOpenChange`, and `disabled`
props.

For a row that also selects a page, pass `isActive={currentPage === "folders"}` and select
the page in `onClick`. Clicking an inactive page opens its section, or leaves it open if it
already is. Clicking the active page toggles the section. Omit `isActive` for a disclosure-only
row that always toggles. This applies to pointer and keyboard activation.
On page-like rows, the chevron is a separate keyboard-accessible button: it only toggles
the section and never calls the page's `onClick` or changes its selection.

Sections unfold and fold over `--duration-slow`: the panel animates its measured height so
the rows below move with it, while its submenu rows fade and clear a 4px blur without sliding.
The submenu's vertical separator stays stationary as the rows animate.
Height animation is intentional here because the navigation layout changes. Base UI retains
the panel through its exit; rapid toggles reverse the transition. Reduced motion uses the
shared 1ms duration tokens. `className` and refs still target the outer panel; the inner
content wrapper exposes `data-slot="sidebar-menu-collapsible-body"`.

## Header composition

A header contains one full-width `SidebarHeaderButton`, or two wrapped in `SidebarHeaderRow`:

```tsx
<SidebarHeader>
  <span>Emails</span>
  <SidebarHeaderRow>
    <SidebarHeaderButton><Plus />Compose</SidebarHeaderButton>
    <SidebarHeaderButton variant="outline"><Search />Search</SidebarHeaderButton>
  </SidebarHeaderRow>
</SidebarHeader>
```

The row owns spacing, sizes buttons from their content and shares the remaining space equally,
and stacks its buttons when the sidebar collapses to
icons. Add `className="flex-none"` when a button should retain its own width. Compose menus with
Dropdown Menu rather than embedding a separate menu implementation in Sidebar.

`SidebarInput` folds away when the sidebar collapses to icons, sliding up under the header
row above it, so it needs no hiding wrapper. Its `className` applies to the input; the fold is
on a `sidebar-input-container` around it, which also drops the header's 8px gap.

### Header tabs

`SidebarTabs` switches the sidebar's contents from a tab row under the title. The root wraps the
header, the panels, and the footer; each `SidebarTabsPanel` usually holds a `SidebarContent`.

```tsx
<SidebarTabs defaultValue="workspace">
  <SidebarHeader>
    <span>Acme Inc</span>
    <SidebarTabsList aria-label="Sections">
      <SidebarTabsTab value="workspace">Workspace</SidebarTabsTab>
      <SidebarTabsTab value="personal">Personal</SidebarTabsTab>
    </SidebarTabsList>
  </SidebarHeader>
  <SidebarTabsPanel value="workspace"><SidebarContent>…</SidebarContent></SidebarTabsPanel>
  <SidebarTabsPanel value="personal"><SidebarContent>…</SidebarContent></SidebarTabsPanel>
  <SidebarFooter>…</SidebarFooter>
</SidebarTabs>
```

| Part | Notes |
| --- | --- |
| `SidebarTabs` | A [Tabs](/docs/tabs) root. `value`, `defaultValue`, `onValueChange`, and `variant` pass through; `appearance` defaults to `outline` and `size` to `sm`. |
| `SidebarTabsList` | Full width, tabs sharing it evenly. Folds away as the sidebar collapses to icons, sliding up under the header row above it (in a `sidebar-tabs-list-container`, which also drops the header's 8px gap); the selected panel stays. |
| `SidebarTabsTab` | One tab, by `value`. |
| `SidebarTabsPanel` | One tab's contents. Inactive panels stay mounted and hidden, keeping scroll position and open sections. |

In split layouts, rail buttons already switch `SidebarPanel`s; tabs can sit inside one panel.

### Pinning the panel open

In split layouts, `hideCollapseHandle` removes the automatically rendered edge strip that toggles
the panel. In non-split layouts, omit your `SidebarRail` instead. Use this when the panel is
pinned open (a controlled `open` that never changes), so there is no control that does
nothing.

```tsx
<Sidebar variant="split-inset" collapsible="icon" hideCollapseHandle={pinned} rail={rail}>
```
