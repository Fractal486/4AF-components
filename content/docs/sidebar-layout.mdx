## API

**Main export:** `SidebarLayout`

A viewport-height application shell around Sidebar. Navigation and the header stay fixed while
the inset content region handles vertical scrolling. The header holds a collapse control on the
left, the page title, and optional actions on the right.

The header is at least 48px tall. When the actions don't fit beside the title, it wraps them onto
another row instead of overflowing. The content column can shrink below its content's width, so
wide content scrolls inside it, and reaching the end of the content doesn't scroll the page. The
column is a [Scroll Area](/docs/scroll-area); `contentClassName` styles its scrolling element.

The outer column has `data-slot="sidebar-layout-content"`; its inner scrolling element has
`data-slot="sidebar-layout-viewport"`. Use the viewport marker for scroll restoration, scroll
position measurements, or scroll locking. The outer column clips content but does not scroll.

| Prop | Purpose |
| --- | --- |
| `title` | Text or a node rendered in the default truncated title slot. |
| `headerContent` | Custom content replacing the title slot, between the collapse control and actions. `null` or `undefined` falls back to `title`. |
| `headerActions` | Controls on the right side of the header. |
| `collapseControl` | Replaces the default `SidebarTrigger`; `null` omits it. |
| `headerClassName` | Classes merged after the default header styling. |

The header uses `bg-surface`, matching the sidebar. Override it through `headerClassName`
when the surrounding shell needs a different background. `headerContent` can hold breadcrumbs,
tabs, or a custom heading without replacing the collapse control or action area.

It is a separate item from `sidebar` so the navigation components can be used without this page
frame. To fit it inside a box instead of the viewport, give the parent a definite height and use
`className="h-full min-h-0"` on `SidebarLayout` to override both the height and the provider's
viewport minimum. Fixed sidebar panels also need a containing block, such as `[contain:paint]`
on the parent, and `className="h-full"` on `Sidebar`.

## The rail slot

The layout has a second region beside the scrolling content, for a full-height detail panel. It
is a sibling of the scroll container rather than a child, so the panel spans the full height and
a footer pinned inside it doesn't scroll away with the content.

Nothing renders there until something portals in. The slot is `display: contents`, so the
portalled panel becomes a direct flex child of the row and sets its own width.

`useSidebarLayoutRailSlot()` returns the slot's mount point, or `null` when it is unavailable.
Prefer the hook to a DOM lookup. `SIDEBAR_LAYOUT_RAIL_SLOT_ID` is exported for code that cannot
access the context.

```tsx
function DetailRail({ children }: { children: ReactNode }) {
  const slot = useSidebarLayoutRailSlot();
  return slot ? createPortal(children, slot) : null;
}
```
