## API

**Main exports:** `Dialog`, `DialogTrigger`, `DialogClose`, and its content, title, and footer
parts; `DialogSteps`, `DialogStep`, and the `DialogPortalContainer` type

A centred modal with enter and exit motion and an optional validated multi-step flow.

`DialogContent.autoSize` is a boolean, defaulting to `true`. Set it to `false` to let
CSS or `style` control the popup height instead of measuring and animating its content.

## Notes

Base UI handles focus trapping, dismissal, scroll locking, and labelling. `DialogContent`
accepts `portalContainer` for a mount point of your own and `backdropClassName` for extra
backdrop styling. Its content sits in a [Scroll Area](/docs/scroll-area) that scrolls when the
dialog is taller than the viewport; `className` styles the popup (width, surface) and
`bodyClassName` the scrolling body (padding `p-6`, gap `gap-4`). The popup's height is measured from its content and transitions when the content resizes; the content stays centred, so the frame grows and shrinks around it. The close button follows the frame's top edge; `DialogFooter` and the step navigation follow its bottom edge. With `autoSize` enabled, leave the height to the component. For a fixed-height or full-screen
viewer, set `autoSize={false}` and provide the popup geometry through `className` or `style`.
This only disables content-height measurement; it does not apply full-screen styling or change
focus trapping, dismissal, scrolling, or enter/exit motion. Switching it off while open removes
the measured height and restores the previous inline height.

```tsx
<DialogContent autoSize={false} className="h-[32rem]">
  <DialogTitle>Preview</DialogTitle>
  {/* Caller-sized content */}
</DialogContent>
```

`DialogSteps` morphs between steps in place (fade, blur, and a slight scale) with no directional travel. Its final **Done**
button closes the dialog after optional validation; it does not save data or submit a form.

`validateStep(index, intent)` receives `"forward"` before advancing and `"submit"` when Done
is pressed. Return `false` to block the operation. A failed submit validation keeps
`DialogContent` open so the user can correct the current step.
